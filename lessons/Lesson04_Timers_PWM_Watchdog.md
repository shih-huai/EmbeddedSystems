# ESP32 韌體與驅動面試速成：第 4 課

## 第 4 課：硬體計時器、PWM、Watchdog

一句話：計時器就是「被時脈推著跑的計數器」，除頻器決定速度、比較值決定何時觸發；PWM 是計時器加上「輸出比較」，watchdog 是「沒人重置就會把晶片重開」的計時器。

### 概念

**計時器參數怎麼算**：計時器每秒跳 `f_clk / prescaler` 次，所以要等 `period` 秒，比較值設成：

```
alarm = f_clk × period / prescaler
```

ESP32 的通用計時器有 4 個（2 個 timer group 各 2 個），64 位元計數、16 位元除頻，時脈是 80 MHz 的 APB。除頻 80 就是 1 µs 一個 tick，1 ms 的 alarm = 1000。面試常要你當場算這個，記得提到「先乘後除、用 64 位元避免溢位」。

**PWM 三個參數**：頻率（一秒幾個週期）、duty（高電位佔週期的比例）、解析度（duty 可以切成幾格）。一個 PWM 週期裡只有 `f_clk / f_pwm` 個時脈，所以頻率和解析度互相牽制：`2^bits × f_pwm ≤ f_clk`。80 MHz 下 5 kHz 最多 13 位元，1 MHz 只剩 6 位元。ESP32 的 PWM 周邊叫 LEDC，有 16 個通道。

常見用途：LED 調光（頻率要高過人眼可察覺的閃爍，數百 Hz 以上）、馬達（常用 20 kHz 以上避開可聽頻率）、伺服馬達（50 Hz，脈寬 1–2 ms）。

**Watchdog**：程式要定期「餵狗」（重置計數），逾時沒餵就重開。ESP-IDF 有三種：

| 種類 | 監看什麼 |
| --- | --- |
| Task WDT（TWDT） | 訂閱的 task 是否定期餵狗；預設也監看 idle task，代表沒有 task 霸佔 CPU |
| Interrupt WDT（IWDT） | 中斷被關太久或 ISR 跑太久 |
| RTC WDT | 開機過程與整個系統的最後防線 |

餵狗策略是面試重點：**不要在計時器 ISR 裡餵狗**，否則主程式卡死了 ISR 還是照餵，watchdog 就沒用。正確做法是在主迴圈「確認各子系統都回報正常」之後才餵。重開後用 `esp_reset_reason()` 記錄原因，現場問題才查得到。

### 面試題與參考答案

**Q1. 時脈 80 MHz，要每 1 ms 產生一次中斷，prescaler 和比較值怎麼設？**
例如 prescaler 80，計時器變 1 MHz，比較值 1000。也可以 prescaler 8000、比較值 10，但解析度變差。原則是在計數器不溢位的前提下用最小的 prescaler，時間解析度最好。

**Q2. PWM 的頻率和解析度為什麼互相牽制？**
一個 PWM 週期裡只有 `f_clk / f_pwm` 個時脈可以拿來切 duty。頻率越高，週期越短，能切的格數越少。等式是 `2^bits × f_pwm ≤ f_clk`。

**Q3. watchdog 應該在哪裡餵？**
在「能證明系統健康」的地方。常見做法是每個重要 task 定期回報一個旗標，由一個監控 task 確認全部收到才餵。不要在計時器 ISR 裡餵，也不要在一個「不管其他人狀態」的迴圈裡無腦餵。

**Q4. 硬體計時器和軟體計時器（FreeRTOS timer、esp_timer）差在哪？**
硬體計時器中斷直接觸發，抖動最小，但數量有限、回呼在 ISR 裡執行。軟體計時器可以開很多個，回呼在 task 裡執行，可以做比較多事，但受排程延遲影響，FreeRTOS timer 的解析度只有一個 tick（預設 1 ms）。

**Q5. 什麼是 input capture？可以拿來做什麼？**
腳位出現邊緣時，硬體自動把當下的計時器值存進暫存器，不受中斷延遲影響。用來量脈寬、頻率、超音波測距的回波時間。ESP32 的 MCPWM 和 RMT 周邊有類似功能。

**Q6. 為什麼 LED 調光要做 gamma 校正？**
人眼對亮度的感知接近對數，線性增加 duty 會覺得一開始亮得很快、後面幾乎沒變。用平方或查表把「感知亮度」轉成 duty，漸變才會平順。也因此需要高解析度，暗部才有足夠的階數。

**Q7. 產品在現場偶爾重開，你怎麼查？**
開機時記錄 `esp_reset_reason()`（上電、brownout、各種 watchdog、panic），存進 NVS 或回傳。開啟 core dump 把當機當下的堆疊存進 flash。brownout 代表電源問題，watchdog 代表有 task 卡住，要分開查。
