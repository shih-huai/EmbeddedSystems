第 6 課：I2C 與 MPU6050 驅動

一句話：I2C 用兩條 open-drain 線（SDA、SCL）掛很多裝置，每次傳輸是「START、位址、ACK、資料、ACK…、STOP」；寫一個 I2C 感測器驅動，就是照資料手冊的暫存器表把這些傳輸組起來。

概念

一次 I2C 傳輸：

  1. START：SCL 為高時，SDA 由高變低。
  2. 7 位元位址 + 1 位元讀寫方向（0 = 寫、1 = 讀）。
  3. 每 8 個位元後，接收方在第 9 個時脈把 SDA 拉低，代表 ACK；沒拉低就是 NACK。
  4. 資料位元組，高位元先送（和 UART 相反）。
  5. STOP：SCL 為高時，SDA 由低變高。

讀暫存器的標準流程：先「寫」暫存器位址，不送 STOP，接著 repeated START 換成「讀」方向。用 repeated START 是為了不讓別的主機在中間搶走匯流排。很多感測器讀完一個暫存器會自動把位址加 1，所以一次可以 burst read 好幾個暫存器，而且保證這些值來自同一次取樣。

為什麼是 open-drain、要上拉電阻：任何裝置都可以把線拉低，但沒有人主動輸出高電位，所以不會有兩個裝置一高一低短路的問題，也能做 ACK 和 clock stretching。上拉電阻太大，上升邊緣太慢（匯流排電容越大越嚴重）；太小，拉低時電流太大。常見 2.2–4.7 kΩ。

Clock stretching：從機還沒準備好時，可以把 SCL 拉住不放，主機要等它放開。不是每個主機控制器都支援得很好，是常見的相容性問題。

匯流排卡死：從機正在送資料時主機被重置，從機還等著時脈把剩下的位元送完，SDA 就一直被它拉低。復原方法是主機手動打最多 9 個 SCL 脈衝，直到 SDA 放開，再送一個 STOP。

速度：標準模式 100 kHz、快速模式 400 kHz、Fast-mode Plus 1 MHz。

驅動的結構：驅動只依賴一組 I2C 函式指標（i2c_bus_t），不直接呼叫 Wire。這樣驅動可以換平台，也能在電腦上用假匯流排測試。這就是「測試與模擬方法」講的 HAL 抽象。

Wokwi 練習 6：自己寫 MPU6050 驅動

程式專案是 Day06_I2C_MPU6050。MPU6050 的 SDA 接 GPIO21、SCL 接 GPIO22，位址 0x68。驅動在 lib/mpu6050，附 5 個用假匯流排的單元測試。

EXERCISE 內容
0 掃描 I2C 匯流排，列出有 ACK 的位址
1 直接用 Wire 讀 WHO_AM_I：寫暫存器位址、repeated START、讀 1 個位元組
2 用驅動每 500 ms 印出加速度、角速度、溫度。在 Wokwi 點 MPU6050 可以拖滑桿
3 錯誤處理：錯的位址得到 NACK；示範匯流排卡死時的 9 個時脈復原

驅動的初始化和讀取：

int mpu6050_init(mpu6050_t *dev, const i2c_bus_t *bus, uint8_t addr) {
  uint8_t id = 0;
  int err = read_regs(dev, MPU6050_REG_WHO_AM_I, &id, 1);   // 先確認是對的晶片
  if (err) return err;
  if (id != 0x68) return MPU6050_ERR_ID;                    // 認錯晶片就不要亂寫
  err = write_reg(dev, MPU6050_REG_PWR_MGMT_1, 0x00);       // 上電預設在睡眠，要喚醒
  if (err) return err;
  return write_reg(dev, MPU6050_REG_ACCEL_CONFIG, 0x00);    // ±2g
}

static int16_t be16(const uint8_t *p) {
  // 大端序：高位元組在前。先組成 uint16_t 再轉 int16_t，負數才正確
  return (int16_t)(uint16_t)((p[0] << 8) | p[1]);
}

單元測試用一份 128 個暫存器的陣列模擬晶片，測了喚醒、NACK、認錯晶片、負數與大端序轉換、匯流排錯誤往上傳，5 個全部通過。

面試題與參考答案

Q1. 描述一次「讀暫存器」的 I2C 傳輸。 START、位址 + W、ACK、暫存器位址、ACK、repeated START、位址 + R、ACK、從機送資料、主機 ACK（要繼續讀）或 NACK（最後一個）、STOP。主機在最後一個位元組回 NACK，是告訴從機「不要再送了」。

Q2. 為什麼 I2C 要用 open-drain 和上拉電阻？上拉電阻怎麼選？ 多個裝置共用同一條線，open-drain 讓任何人拉低都不會短路，也才能做 ACK、仲裁、clock stretching。電阻值由匯流排電容和速度決定：上升時間約等於 RC，400 kHz 要求 300 ns 內，電容大就要用小電阻；下限受晶片能吸收的電流（通常 3 mA）限制。

Q3. I2C 匯流排卡住（SDA 一直是低），怎麼辦？ 通常是從機在傳輸中途沒收到剩下的時脈。主機把 SCL 當 GPIO，打最多 9 個時脈直到 SDA 放開，再送 STOP，然後重新初始化 I2C 控制器。如果還是不行，就重新上電從機（設計時可以讓 MCU 控制感測器電源）。

Q4. 兩個裝置同一個位址怎麼辦？ 很多晶片有位址腳（例如 MPU6050 的 AD0）可以改位址。不行的話用 I2C 多工器（例如 TCA9548A）分成多段匯流排，或放到 ESP32 的第二組 I2C 控制器上。

Q5. 什麼是 clock stretching？會造成什麼問題？ 從機把 SCL 拉低不放，讓主機等它準備好資料。如果主機控制器不支援或逾時設太短，就會讀到錯的資料或回報逾時。驅動要設合理的逾時，而且逾時後要能復原匯流排。

Q6. 為什麼讀加速度要一次 burst read 14 個位元組，不分開讀？ 分開讀時，晶片可能在兩次讀之間更新了數值，X 和 Y 就來自不同的取樣；而且高低位元組分開讀，可能讀到新的高位元組配舊的低位元組。burst read 加上晶片的資料鎖存，可以保證一致性，也少了很多次 START 和位址的開銷。

Q7. 你怎麼測一個 I2C 感測器驅動，手邊沒有硬體？ 把匯流排抽象成函式指標，測試時換成假匯流排：用陣列模擬暫存器，記錄被寫入的值，也能模擬 NACK、錯誤的 WHO_AM_I。這樣可以驗證初始化順序、位元組序、錯誤處理。最後再用 Wokwi 或實體板做整合測試，用邏輯分析儀看波形。
