ESP32 韌體與驅動面試速成：第 7 課

第 7 課：SPI 與 ILI9341 螢幕驅動

一句話：SPI 是主機送時脈、全雙工、沒有位址也沒有 ACK 的高速匯流排，用 CS 線選裝置；寫螢幕驅動的關鍵是「少發指令、多連續送資料」。

概念

四條線：SCK（主機送出的時脈）、MOSI（主機送、從機收）、MISO（從機送、主機收）、CS（低電位選中某個從機，每個從機一條）。每個時脈同時送出一個位元也收進一個位元，所以是全雙工：想讀資料，主機也得送出等量的位元（通常送 0x00 或 0xFF）。

四種模式（CPOL、CPHA）：

模式 CPOL（閒置時 SCK） CPHA（在哪個邊緣取樣）
0 低 第一個邊緣（上升）
1 低 第二個邊緣（下降）
2 高 第一個邊緣（下降）
3 高 第二個邊緣（上升）

模式要照從機資料手冊設定，大多數裝置是模式 0，SD 卡和很多 flash 也支援模式 3。設錯模式的典型症狀是資料差一個位元（整體左移或右移）。

SPI 和 I2C 比較：SPI 快很多（幾十 MHz vs 400 kHz）、全雙工、沒有協定開銷，但線比較多（每個裝置多一條 CS），也沒有 ACK，送錯了不知道。I2C 兩條線可以掛很多裝置，適合低速感測器。

ILI9341 的協定：除了 SPI，還多一條 D/C 線，0 代表這個位元組是指令，1 代表是資料。畫圖的流程是：

  1. CASET（0x2A）設定欄的起點和終點，PASET（0x2B）設定列的起點和終點，座標用 16 位元大端序。
  2. RAMWR（0x2C）之後，連續送的資料就是像素，螢幕自動在視窗裡往下一格填。
  3. 每個像素是 RGB565 共 16 位元，高位元組先送。

所以畫一個像素要 3 個指令加 10 個位元組參數，畫一整塊卻只要多送像素資料。效能差異在練習 2 裡看得到。

ESP32 的 SPI：有 4 組 SPI 控制器，SPI0/1 給 flash 用，可用的是 HSPI 和 VSPI。用 IO_MUX 原生腳位可以跑到 80 MHz，經過 GPIO matrix 建議不要超過 40 MHz（第 2 課提過的延遲問題）。

Wokwi 練習 7：自己寫螢幕驅動

程式專案是 Day07_SPI_ILI9341。ILI9341 接 VSPI（SCK=18、MOSI=23、MISO=19），CS=17、D/C=16、RST=4。驅動在 lib/ili9341，附 6 個用假匯流排的單元測試。

EXERCISE 內容
0 輪流填滿紅綠藍，印出每次填滿的時間
1 比較 SPI 10、20、40 MHz 的填滿時間，和理論值對照
2 同一塊 100x100：逐點畫 vs 一次 fill_rect
3 彈跳方塊動畫：只擦舊位置、畫新位置

填滿整個畫面是 240 × 320 × 2 = 153,600 位元組，40 MHz 下理論上要 30.7 ms。實際會比較慢，因為 CS、D/C 切換和每段傳輸之間都有空檔，第 8 課會用 DMA 改善。

驅動的核心是「設定視窗後連續送像素」：

set_window(dev, x, y, x + w - 1, y + h - 1);   // CASET + PASET
cs(0); dc(0); write(RAMWR);                     // 開始寫像素
dc(1);
while (left) {                                  // 同一段緩衝區重複送，不用整張畫面那麼大的記憶體
  uint32_t n = left > CHUNK ? CHUNK : left;
  write(buf, n * 2);
  left -= n;
}
cs(1);

單元測試的假匯流排會記錄每個指令和資料，檢查初始化順序、視窗座標的位元組（例如 300 要送成 0x01 0x2C）、像素數量、超出螢幕時的裁切，以及在 CS 沒選中時有沒有亂送資料，6 個全部通過。

面試題與參考答案

Q1. SPI 的 CPOL、CPHA 是什麼？設錯會怎樣？ CPOL 是閒置時時脈的電位，CPHA 決定在第一個還是第二個邊緣取樣。主從兩邊要一致；設錯時取樣點落在資料變化的地方，常見症狀是資料錯一個位元、整體位移，或時好時壞。

Q2. SPI 為什麼比 I2C 快？代價是什麼？ SPI 是推挽輸出，邊緣很陡，能跑到幾十 MHz；沒有位址、ACK、START/STOP，幾乎沒有協定開銷；全雙工。代價是線多（每個從機一條 CS）、沒有 ACK 不知道對方有沒有收到、沒有標準的定址和錯誤處理，長距離訊號完整性較差。

Q3. 一個 SPI 匯流排掛多個裝置，要注意什麼？ 每個裝置一條 CS，同一時間只能選中一個。不同裝置可能要不同的模式和時脈，所以每次傳輸前要重新設定（Arduino 的 beginTransaction 就是做這件事）。多個 task 共用匯流排要加鎖。沒被選中的從機 MISO 要是高阻抗，否則會互相干擾。

Q4. 為什麼逐點畫圖很慢？怎麼改？ 每個像素都要送 CASET、PASET、RAMWR 三個指令和參數，還要切換 CS 和 D/C，真正的像素資料只佔一小部分。改法是設定一次視窗後連續送像素、合併相鄰的繪圖、用 framebuffer 在記憶體裡畫好再整塊送，進一步用 DMA 讓 CPU 不用等。

Q5. RGB565 是什麼？為什麼常用？ 16 位元表示一個像素：紅 5 位元、綠 6 位元、藍 5 位元（人眼對綠色最敏感，所以多一位）。比 24 位元省三分之一的頻寬和記憶體，對小螢幕畫質足夠。要注意位元組序：SPI 高位元組先送，而 ESP32 是小端序，直接把 uint16_t 陣列丟給 SPI 會送反。

Q6. 怎麼確認 SPI 驅動送的東西是對的？ 單元測試用假匯流排記錄送出的位元組，對照資料手冊的指令序列；整合時用邏輯分析儀抓 SCK、MOSI、CS、D/C，配合 SPI 解碼器看每個位元組。模式設錯或 D/C 時序錯，在波形上一眼就看得出來。
